# Подготовка к защите Study Atlas

## Что делает проект

Study Atlas — каталог мест для учёбы. Пользователь ищет место по названию или району, фильтрует по городу, типу, атмосфере, цене и Wi-Fi, меняет порядок сортировки, открывает подробную страницу, сохраняет понравившееся место и добавляет своё.

В проекте одна симулированная API: `src/lib/api.js`. Она использует Promise, задержки, JSON со 120 записями и localStorage. Данные демонстрационные, новые места сохраняются только в этом браузере.

## Компоненты и состояние

- `App` соединяет страницы, хранит счётчик обновлений каталога и сообщение об успешном добавлении.
- `Header` получает маршрут и число сохранённых мест через props.
- `Explorer` хранит поисковый запрос, фильтры, сортировку, страницу и состояние восстановления данных.
- `FilterBar` получает значения и обработчик изменения через props.
- `PlaceCard` получает место, состояние избранного и обработчик сохранения.
- `Pagination` получает текущую страницу, число страниц и обработчик перехода.
- `PlaceDetail` загружает отдельное место по ID и хранит состояние подсказки перед посещением.
- `PlaceForm` хранит значения полей, ошибки валидации и статус отправки.
- `useFavorites` хранит массив сохранённых ID. Список и подробная страница используют одно состояние.
- `useRoute` хранит текущий hash-маршрут и подписывается на `hashchange`.

Состояние размещено близко к компонентам, которые им пользуются. Общий список избранного доступен карточкам и странице места, поэтому hook вызывается в `App`. Форма не зависит от состояния фильтров.

## Controlled inputs и события

У текстовых полей и select есть `value` и `onChange`, у checkbox — `checked` и `onChange`. Значение берётся из React state. Обработчик `change` создаёт новый объект через spread, а не меняет существующий.

`onSubmit` вызывает `preventDefault`, проверяет поля и запускает асинхронное сохранение. Кнопка и fieldset блокируются во время запроса. ID создаётся через `crypto.randomUUID`, текст обрезается через `trim`, числовые поля преобразуются в числа. Новое место получает рейтинг 0, который отображается как `New`.

## Как API доходит до UI

`Explorer → placesApi.list → useAsync → PlaceCard`.

Изменение фильтра создаёт новый объект `filters` и сбрасывает страницу на первую. `useCallback` создаёт request с актуальными зависимостями. `useAsync` запускает этот request в `useEffect`, а после успешного ответа сохраняет `data` и `status`.

`queryPlaces` сначала фильтрует записи, затем сортирует копию массива и только потом выделяет страницу. Число страниц вычисляется по отфильтрованному списку. При уменьшении списка текущая страница ограничивается допустимым диапазоном.

## useEffect, dependencies и cleanup

Effect выполняется после commit. В `useAsync` зависимости — ключ запроса и функция `request`. Если запрос, страница, избранное или счётчик обновления меняются, старый effect очищается и запускается новый.

Cleanup вызывает `controller.abort()`. Симулированная API очищает таймер и отклоняет Promise с `AbortError`. Обработчик ответа также проверяет `signal.aborted`, чтобы устаревший запрос не перезаписал результат нового.

`useRoute` удаляет обработчик `hashchange` при размонтировании. Таймер уведомления очищается при изменении сообщения и размонтировании. `PlaceForm` отменяет ожидающий запрос, если пользователь уходит со страницы. Отменённое добавление не записывает данные.

В режиме разработки `StrictMode` может запускать цикл setup → cleanup → setup для effects. Отмена запросов позволяет безопасно пройти этот цикл.

## Render, commit и повторная отрисовка

Render — React вызывает компоненты и вычисляет JSX. Commit — React применяет необходимые изменения к DOM. Изменение state вызывает новый render компонента; его дочерние компоненты также могут быть вычислены заново. После commit запускаются effects.

State представляет снимок конкретного render. Если новое значение зависит от предыдущего, используется функциональный updater, например `setRevision(value => value + 1)`. React может объединить несколько обновлений одного события в batch.

## Keys и идентичность

В каталоге используется `key={place.id}`, а не индекс массива. После сортировки React связывает карточку с тем же местом по ID. Для подробной страницы применяется `key={placeId}`: при переходе к другому месту локальное состояние страницы сбрасывается.

`Explorer` остаётся смонтированным и скрывается при открытии формы или подробностей. Поэтому поиск, фильтры и страница сохраняются при возврате. Форма размонтируется при уходе, поэтому новое открытие начинает ввод с пустых значений.

## Loading, error, empty, success

- Loading: skeleton карточек и индикатор запроса.
- Error: читаемое сообщение, повторный запрос, восстановление демонстрационного каталога при повреждённых данных.
- Empty: объяснение отсутствия результатов и кнопка сброса фильтров.
- Success: каталог с данными; после добавления — уведомление и подробная страница нового места.

Ошибки storage не скрываются под успешным сохранением. Восстановление каталога требует подтверждения внутри интерфейса, поскольку удаляет добавленные места.

## Демонстрация на защите

1. Открыть приложение по публичной ссылке и показать 120 записей.
2. Найти `reading`, выбрать Almaty, Library, Quiet, Free entry и Wi-Fi.
3. Сбросить фильтры, выбрать сортировку по цене и перейти на следующую страницу.
4. Открыть карточку, показать описание, удобства, часы и цену.
5. Сохранить место и открыть Saved.
6. Открыть форму, отправить пустые поля и показать ошибки.
7. Заполнить форму, добавить место и показать уведомление.
8. Перезагрузить страницу и показать сохранённое место и избранное.
9. Ввести несуществующее название и показать empty state.
10. Показать код cleanup в `useAsync` и пройти путь данных от API к карточке.
